港漂打工人兼奶爸，也都是自学 AI 做的。

前一阵把自己的 AI 工具对比站（myaishome.com）动效和首页排版重新搞了一遍。不是炫技，是踩了一堆坑之后总算落地了。这次把全过程做成了 8 张图，左滑看完。

之前站点是纯静态的，工具页、博客、模型库都有，但是说实话，页面看起来像 2018 年的产物。我自己打开都觉得"这站是有人维护的吗"。

这次改了三件事：

第一件，滚动进场动效。原生 JS 30 行就搞定，卡片往下滚的时候错峰淡入上浮，给人"这页面是活的"的感觉。关键是加了 prefers-reduced-motion 守卫，开了系统级"减少动效"的用户直接看静态版。搜索框那次踩了坑——每次输入都重新渲染卡片，动效跟着闪，后来定了个铁律：搜索时不带进场，筛选和首次渲染才带。

第二件，配色。禁了蓝紫渐变那套 SaaS 配方，定了反 SaaS 美学：暖纸白 + 墨黑 + 柿子橙 + 鼠尾草绿。具体色值都在图里。没用居中三卡模板，做了错落 Bento。

第三件，首页底部藏了个数字雨彩蛋。零依赖 React 组件，130 行，柿子橙 + 沙金拖尾，字符池是 0/1 + 少量汉字（AI 江湖侠道悟算）。性能守卫必须做齐：离视口暂停、后台暂停、reduced-motion 静态帧、DPR 上限 2、移动端降字号。少做一条移动端就烫手。

中间踩了个大坑——上线第二天首页白屏。HTTP 200 但页面是空的，控制台不报错。Vite 多入口构建时某个 chunk 引用了一个不在 manifest 里的资源，import 阶段静默失败。这次学到的是：Vite 多入口构建，每改一次 build，必须三步核对——所有 assets 在 git ls-files 里、HTML 引用的 chunk 都在 build 输出里、每个文件都被 git add 进 commit。具体哪三步看图 7。

用到的 Skills 也提一下：flowchart-maker 画组件关系图、lanshu-animated-architecture-diagram 画构建产物核对流程 GIF、impeccable 做配色审计。这几个确实省了 Google + 试错的工夫。

最大的感受是：动效只是表面，工程纪律才是底层。代码写漂亮不重要，构建链路核对完整才重要。
