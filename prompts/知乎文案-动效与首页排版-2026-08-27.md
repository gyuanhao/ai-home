## 为啥要改

之前站点是纯静态的，工具页、博客、模型库都有，但是说实话，页面看起来像 2018 年的产物。我自己打开都觉得"这站是有人维护的吗"。

我也不是非要花哨，但是这年头大家审美被各种 SaaS 产品拉高了，一个白底 + 黑字 + 蓝色超链的页面，第一眼就让人觉得不靠谱。我那站本来流量就靠社媒评论区发链接硬撑着，再看起来旧，点进来的人两秒就关了。

正好 WorkBuddy 有几个现成的 skill 能用上，干脆一拍脑门，做。

## 第一阶段：先做最低成本的滚动进场动效

这一步没动 React，是纯原生 JS。思路很简单：用户往下滚的时候，卡片错峰淡入上浮一下，给人"这页面是活的"的感觉。

写了个 reveal.js，核心就 30 行：

```js
var io = new IntersectionObserver(function (entries) {
    entries.forEach(function (en) {
        if (en.isIntersecting) {
            en.target.classList.add('in');
            io.unobserve(en.target);
        }
    });
}, { threshold: 0.08, rootMargin: '0px 0px -40px 0px' });
Array.prototype.forEach.call(els, function (el, i) {
    el.style.transitionDelay = ((i % 4) * 60) + 'ms';
    io.observe(el);
});
```

关键是 `(i % 4) * 60` 这个延迟——卡片按 4 列分行错峰，每张比上一张晚 60ms 进场，看起来比同时全弹出来顺得多。所有卡片都用同一个 class `reveal`，进了视口加 `in` 类，CSS 那边就一个透明度 + transform 过渡。

接进了三个页：工具库、白皮书、模型库。改完之后没动其他逻辑，纯视觉。

**但是有个坑**：一开始没加 `prefers-reduced-motion` 守卫，给那些开了系统级"减少动效"的用户看会很难受。后来补了——`@media (prefers-reduced-motion: reduce) { .reveal { transition: none } }`，让这类用户直接看到静态版，不动了。这点别漏。

还有个不那么明显但更要命的坑：搜索框即时渲染的时候，因为每次输入都重新渲染卡片，如果带进场动画，每输一个字卡片就闪一下，体验极差。后来定了个铁律——**搜索时调 `render(false)` 不带进场，筛选和首次渲染才 `render(true)` 带进场**。这个细节不解决，动效就是反效果。

完整版我写在博客里了，包括分类筛选的淡出重排怎么处理：https://myaishome.com/blog/ai-coding-tools-experience-2026

## 第二阶段：上 Aceternity UI 重做首页

原生 JS 动效跑顺之后，野心起来了，想给首页也整个大改造。

我直接选了 Aceternity UI——这玩意是个 copy-paste 的 React 组件库，不是 npm 包（这个我之前理解错了，以为能 import，结果发现 `aceternity-ui` 在 npm 上其实是个 CLI 工具，不是组件库本身）。组件代码都在它官网，自己拷过来改。

策略是分阶段来，不一次梭哈：

**第一步**：先做一个独立的 `/showcase` 展示馆页面，纯 React 孤岛，跟主站完全隔离，就算挂了也不影响主站。把 Aceternity 的旗舰组件全部 1:1 复刻进去——Aurora Background、3D Card、Bento Grid、Spotlight、Hover Card、Moving Border、Magnetic、Glowing Effect、Text Generate Effect、Noise Background、Floating Navbar……一个一个手抄过来，丢到 `showcase-src/src/components/ui/` 里。

跑通了，没炸。这一步最大的收获是搞清楚了 React + Tailwind + framer-motion 的工程链怎么搭。

**第二步**：把首页翻新。

这一步是真正的硬仗。配色是先定的——反 SaaS 美学，**明确禁了蓝紫渐变、纯平背景、居中三卡、emoji 图标**那套配方。最后定的：

- 暖纸白 #FAF7F2（不是纯白，纯白太刺眼）
- 墨黑 #1A1A1A
- 柿子橙 #E8542C（主色调，CTA 都用这个）
- 鼠尾草绿 #4A7C59（次要色，hover 状态用）

布局没学那种"Hero 居中 + 下面三张等高卡"的模板，做了**左偏 Hero + 手绘下划线 + 错落 Bento + 横滚博客**。Hero 区是 StaggerReveal 把标题、副标、CTA 依次错峰进场，下面 Bento 用了 4 种不同尺寸的卡，最大的那张放最新博客，小的放分类入口。

中间又加了个我挺得意的小彩蛋——首页底部那个仙侠 section，背景是 React 写的 Matrix 数字雨。零依赖，一个 canvas + 130 行代码，柿子橙 + 沙金拖尾，字符池是 0/1 二进制 + 少量汉字（"AI 江湖侠道悟算"）。

这里有个性能坑必须避：**IntersectionObserver 离开视口要暂停、`visibilitychange` 切后台要暂停、`prefers-reduced-motion` 要静态帧、devicePixelRatio 上限 2、移动端降字号 13px**。少做一条，移动端就烫手。

## 第三阶段：白屏事故与回退

第二步做完上线，第二天打开首页白屏。

排查发现是 React.useRef 缺失 + framer-motion 依赖在某些 chunk 里没正确打包。具体说就是 Vite 多入口构建时，某个 chunk 引用了一个不在 manifest 里的资源，import 阶段静默失败，root 节点直接空——**HTTP 200 但页面是空的，控制台不报错**。

这次踩坑学到的是：**Vite 多入口构建，每改一次 build，必须三步核对**：

1. build 输出的所有 assets/* 都在 git ls-files 里
2. 每个 HTML 引用的 chunk 路径都在 build 输出里
3. build 输出的每个文件都被 git add 进 commit

最阴的是第 2 条——我之前从不同时间点的 build 产物拼凑文件，git 里 add 的是新 hash，但 HTML 里引用的是旧 hash，生产环境 404 整页白屏，但浏览器看着是"HTTP 200 + 空白"，没报错。

验证脚本一行：

```
comm -12 <(git ls-files assets/ | sort) <(ls home-new/assets/ | sort)
```

两边必须完全相同。还有要在浏览器里跑 `performance.getEntriesByType('resource')` 查所有 chunk 的 responseStatus，404 在 import 阶段静默失败，光看 Network 面板的绿色对勾是骗你的。

## 用到的 Skills

整个过程我用了 WorkBuddy 里几个 skill，必须提一下，确实省了我事：

**flowchart-maker skill**——画首页组件关系图的时候用的，Mermaid 转 HTML/CSS 交互式流程图，10 个主题可选。我画了"用户滚动 → IntersectionObserver 触发 → 错峰延迟 → CSS 过渡"这条链路的流程图，比文字描述清楚太多。这个 skill 的好处是产出的流程图本身就是 HTML，可以直接嵌进博客。

**lanshu-animated-architecture-diagram skill**——这个偏架构图，手绘风，能输出 GIF。我用它画了 Vite 多入口构建的产物核对流程，那个"build → git ls-files → HTML 引用 → 浏览器 import"的三步核对链路，用静态图说不清，GIF 一演示立刻明白。

**impeccable skill**——这玩意是个设计审计工具，我用在配色那一步。把暖纸白+柿子橙+鼠尾草绿这套方案丢进去，它会按中西方美学 + 品牌 VI + 设计系统的维度审一遍，告诉我对比度够不够、色相是否协调、跟主站其他页是否冲突。它说我那套"鼠尾草绿 hover 太冷，跟暖纸白主基调违和"，我后来调成了更暖一点的橄榄绿，确实更顺。

老实说不是每个 skill 都神效，但至少这几步少走了我自己 Google + 试错的工夫。

## 几句实在话

这次搞完之后最大的感受不是"动效多酷"，是"细节比想象中多"。

prefers-reduced-motion 这种守卫，新手 99% 会漏；搜索框的 render(false) / render(true) 区分，不到实战踩坑也想不起来；Vite 多入口构建产物的三步核对，是我白屏事故之后才学到的——这些细节加起来，比那 130 行 Matrix 数字雨本身重要得多。

所以你要做类似的事，记住一句话：**动效只是表面，工程纪律才是底层**。代码写漂亮不重要，构建链路核对完整才重要。
