## 一、总体思路（一句话先看懂）

把现在"翻网页"的体验，改成"在仙侠世界地图上走动、点击地点触发内容"。

- **地图与行走** = 体验外壳（吸引人、有沉浸感）
- **原网站的模型库 / 对比 / 技能包 / 博客 / 新闻等内容** = 玩家进入对应"地点"后，用**内容面板**弹出展示

也就是：**游戏做导航和氛围，内容面板做信息**。不把长篇对比表、博客文章硬塞进游戏画面（那样阅读体验很差），而是"走过去 → 触发 → 弹面板看内容"。

原网页板块 → 游戏地点的对应（名字可后续一起定）：

| 原网页 | 游戏地点（暂定） | 场景文件 |
|---|---|---|
| models.html 模型库 | 万象阁 | ModelPavilionScene |
| compare.html 对比 | 论剑台 | CompareArenaScene |
| skills.html 技能包 | 秘籍阁 | SkillLibraryScene |
| blog/ 博客 | 藏经阁 | BlogAcademyScene |
| news.html 新闻 | 风云榜 | NewsHallScene |
| picker.html 选择器 | 问道路 | PickerPathScene |
| about + 法律页 | 迎宾客栈 | AboutInnScene |

## 二、技术栈与可行性（实话实说，不美化）

- **Phaser 3**：成熟的 2D 游戏引擎，做"顶视角地图 + 角色行走 + 区域触发"完全可行，中文教程多。
- **局限 / 你要心里有数的点**：
  1. **美术资源要自己解决**（地图瓦片、角色精灵、UI 图标）。这是主要工作量。建议分期：先用免费占位素材跑通全部逻辑，逻辑没问题后再换正式美术。
  2. **长内容**（模型参数表、博客长文）在游戏画面里直接看体验差 → 用"内容面板"弹窗承载，保留结构化排版。
  3. **移动端**：Phaser 画布能缩放适配，但"点地图走路"在手机上要额外做触控优化（虚拟摇杆 or 点击移动），这块后续单独一轮讨论。
  4. **开发量不小**：372 个原页面的内容要迁移/重组进 data 层，游戏逻辑要新写。会分阶段交付，每阶段你能本地预览。

## 三、⚠️ 最关键的架构权衡（请你拍板，会影响整体结构）

**游戏化体验 vs SEO 引流，有冲突。**

- 你这个站目前主要靠**搜索引擎引流**（已在做 AdSense、GSC/Bing 验证、sitemap）。
- 游戏化页面的内容靠 JS/Canvas 动态渲染，**搜索引擎爬虫很难抓取** → 游戏化越彻底，SEO 流量可能越受损。
- **折中建议（双轨）**：内容数据（models.json 等）只维护一份，同时干两件事——
  - 喂给游戏场景展示（玩家看到的）
  - 自动注入"结构化数据(JSON-LD) + 静态可见文本"到页面 HTML（爬虫抓到的）
- 这就是为什么目录里有个 `SEOBooster.js` 模块。

→ **请你先就这一点表个态**：
- A. 接受"双轨"（游戏 + SEO 兼顾，推荐）
- B. 纯游戏化优先，SEO 以后再说
- C. 其他想法

（这不算"抛一堆需求问题"，是结构确认前必须定的一个分叉。）

## 五、各部分说明（零基础向）

### 5.1 场景分层管理（src/scenes/）

Phaser 用"场景(Scene)"组织画面，像电影的分镜。每个场景是一个独立文件，互不干扰，按顺序切换。

- **BootScene（启动页）**：游戏一启动先进这里。做最基础的初始化（设渲染参数、加载第一张占位图），然后跳去 Preload。停留极短，玩家几乎看不到。
- **PreloadScene（资源加载页）**：集中加载所有美术、音效、地图数据，显示进度条。加载完跳主菜单。
- **MenuScene（主菜单）**：游戏化的氛围入口。"开始闯荡 / 继续 / 设置"。这是玩家第一眼看到的有设计画面。
- **WorldMapScene（地图主场景）**：核心。一张仙侠世界地图，玩家角色在上面走，地图上散布若干"地点图标"。走到地点触发区 → 进入对应地点场景。
- **locations/（地点场景）**：每个原网页板块一个场景。进入后展示该板块内容（用 ContentPanel 弹面板，保留排版）。看完可"退出"回世界地图。

**为什么这样分**：场景互相独立，加一个新地点 = 加一个文件 + 在 mapConfig 登记一行，不动其他东西。这就是"03-如何新增一个地图地点.md"要教你的事，迭代最常用。

### 5.2 模块化组件（src/entities/）

游戏里反复出现的"东西"封装成类，改一处、处处生效。

- **Player**：玩家角色。管移动、朝向、行走动画、和地图边界/障碍碰撞。
- **NPC**：地图上的引导角色。站桩，靠近可对话/指引。
- **MapLocation**：一个"地点"。管它的图标、名字、触发范围、点进去去哪个场景。
- **TriggerZone**：隐形触发区。玩家一踩进去就触发事件（弹面板或切场景）。

### 5.3 系统服务（src/systems/）

不和某个场景绑死的通用能力，所有场景都能调用。

- **SceneManager**：统一管场景切换（带过渡、传参数、回退到上一张地图）。
- **ContentPanel**：内容面板。原网页的内容（模型卡、对比表、博客）在这里以弹窗形式展示，保留可读排版。**这是"游戏外壳 + 内容底座"的交汇点。**
- **InputController**：统一处理键盘、鼠标、触屏输入，适配移动端。
- **SaveSystem**：存档。记玩家去过哪些地点、设置项。
- **AudioManager**：背景音乐和音效的统一控制。
- **SEOBooster**：把 data 层数据写成 JSON-LD 结构化数据 + 静态可见文本，注入页面，让搜索引擎能抓到核心内容（双轨方案的落地处）。

### 5.4 数据层（src/data/）

原网站的结构化内容全部搬到这里，**改内容只改数据文件，不碰代码**。

- `models.json`：AI 模型列表（从 ai-home/scripts/models.json 迁移）。
- `skills.json`：技能包数据。
- `articles.json`：博客/新闻文章。
- `mapConfig.json`：地图配置——哪些地点、各自坐标、名字、图标、对应哪个场景。**加新地点主要改这里。**

### 5.5 资源 / 第三方库 / 文档

- `assets/`：所有美术和音效。分 tiles/sprites/ui/locations/audio/maps。
- `vendor/phaser.min.js`：Phaser 引擎本地存放，不依赖 CDN（部署后也稳定）。
- `docs/`：零基础教学文档。其中 `03-如何新增一个地图地点.md` 是你以后最常翻的。
